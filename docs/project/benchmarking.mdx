Bun 专为速度而设计。热点路径经过广泛的性能分析和基准测试。Bun 所有公开基准测试的源代码都位于 Bun 仓库的 [`/bench`](https://github.com/oven-sh/bun/tree/main/bench) 目录中。

## 测量时间

为了精确测量时间，Bun 提供了两个运行时 API：

1. 符合 Web 标准的 [`performance.now()`](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now) 函数
2. `Bun.nanoseconds()`，它类似于 `performance.now()`，但返回的是应用程序启动以来经过的时间，单位为纳秒。使用 `performance.timeOrigin` 可将其转换为 Unix 时间戳。

## 基准测试工具

- 对于微基准测试，我们推荐使用 [`mitata`](https://github.com/evanwashere/mitata)。
- 对于负载测试，你 _必须使用_ 至少与 `Bun.serve()` 一样快的 HTTP 基准测试工具，否则测试结果会产生偏差。一些流行的基于 Node.js 的基准测试工具（例如 [`autocannon`](https://github.com/mcollina/autocannon)）速度不够快。我们推荐使用以下工具之一：
  - [`bombardier`](https://github.com/codesenberg/bombardier)
  - [`oha`](https://github.com/hatoo/oha)
  - [`http_load_test`](https://github.com/uNetworking/uSockets/blob/master/examples/http_load_test.c)
- 对于基准测试脚本或 CLI 命令，我们推荐使用 [`hyperfine`](https://github.com/sharkdp/hyperfine)。

## 测量内存使用

Bun 有两个堆：一个用于 JavaScript 运行时，另一个用于其他所有内容。

import { heapStats } from "bun:jsc";

JavaScript 是一种垃圾回收语言，不是计数引用。对象在所有情况下不立即释放是正常且正确的，尽管对象永远不被释放是不正常的。

要强制手动运行垃圾回收：

```ts
Bun.gc(true); // 同步执行
Bun.gc(false); // 异步执行
```

堆快照可以显示哪些对象没有被释放。使用 `Bun.generateHeapSnapshot()` 获取堆快照，然后使用 Safari 或 WebKit GTK 开发者工具查看。生成堆快照：

```ts
import { generateHeapSnapshot } from "bun";

const snapshot = generateHeapSnapshot();
await Bun.write("heap.json", JSON.stringify(snapshot, null, 2));
```

要查看快照，请在 Safari 的开发者工具（或 WebKit GTK）中打开 `heap.json` 文件：

1. 打开开发者工具  
2. 点击「Timeline」（时间轴）  
3. 在左侧菜单点击「JavaScript Allocations」（JavaScript 分配）。可能需要点击铅笔图标才能显示所有时间轴  
4. 点击「Import」（导入），选择你的堆快照 JSON

## CPU 性能分析

使用 `--cpu-prof` 标志分析 JavaScript 执行性能，以识别性能瓶颈。

```sh terminal icon="terminal"
bun --cpu-prof script.js
```

`--cpu-prof` 会写入一个 `.cpuprofile` 文件，你可以在 Chrome DevTools（性能面板 → 加载配置文件）或 VS Code 的 CPU 分析器中打开该文件。

### Markdown 输出

使用 `--cpu-prof-md` 来生成 markdown 格式的 CPU 分析报告，这种格式便于 grep，且适合大型语言模型（LLM）分析：

```sh terminal icon="terminal"
bun --cpu-prof-md script.js
```

同时使用 `--cpu-prof` 和 `--cpu-prof-md` 可一次生成两种格式：

```sh terminal icon="terminal"
bun --cpu-prof --cpu-prof-md script.js
```

你也可以通过 `BUN_OPTIONS` 环境变量传递该标志：

```sh terminal icon="terminal"
BUN_OPTIONS="--cpu-prof-md" bun script.js
```

### 选项

```sh terminal icon="terminal"
bun --cpu-prof --cpu-prof-name my-profile.cpuprofile script.js
bun --cpu-prof --cpu-prof-dir ./profiles script.js
```

| 标志                         | 说明                                 |
| ---------------------------- | ------------------------------------ |
| `--cpu-prof`                 | 生成 `.cpuprofile` JSON 文件（Chrome DevTools 格式） |
| `--cpu-prof-md`              | 生成 markdown 格式的 CPU 分析报告      |
| `--cpu-prof-name <filename>` | 设置输出文件名                        |
| `--cpu-prof-dir <dir>`       | 设置输出目录                          |

## 堆分析

退出时写入堆分析文件，以分析内存使用情况并查找内存泄漏。

```sh terminal icon="terminal"
bun --heap-prof script.js
```

`--heap-prof` 会在退出时写入完整的 V8 格式堆快照，使用 Node.js 的诊断文件名格式（`Heap.<yyyymmdd>.<hhmmss>.<pid>.<tid>.<seq>.heapprofile`）。其内容与 `v8.writeHeapSnapshot()` / `Bun.generateHeapSnapshot("v8")` 相同：通过「Memory」选项卡 →「Load」在 Chrome DevTools 中加载该文件（选择「All Files」或将文件重命名为 `.heapsnapshot`——扩展名遵循 Node 的 `--heap-prof` 文件名约定，测试框架和工具会根据此约定进行识别）。

### Markdown 输出

使用 `--heap-prof-md` 来生成 CLI 友好的 Markdown 堆分析报告：

```sh terminal icon="terminal"
bun --heap-prof-md script.js
```

<Note>如果同时指定了 `--heap-prof` 和 `--heap-prof-md`，则以 Markdown 格式为准。</Note>

### 选项

```sh terminal icon="terminal"
bun --heap-prof --heap-prof-name my-profile.heapprofile script.js
bun --heap-prof --heap-prof-dir ./profiles script.js
```

| 标志                           | 说明                                                                                                                                       |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `--heap-prof`                  | 在退出时写入 `.heapprofile` 文件                                                                                                        |
| `--heap-prof-md`               | 在退出时生成 Markdown 堆分析文件                                                                                                       |
| `--heap-prof-name <filename>`  | 设置输出文件名                                                                                                                        |
| `--heap-prof-dir <dir>`        | 设置输出目录                                                                                                                       |
| `--heap-prof-interval <bytes>` | 为兼容 Node.js 而接受（快照只会在退出时获取一次；JavaScriptCore 没有可应用间隔的分配采样功能） |

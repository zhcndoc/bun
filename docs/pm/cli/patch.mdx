`bun patch` 以可维护、对 Git 友好的方式持久化修补 `node_modules` 中的包。

有时你需要对 `node_modules/` 中的包进行小幅修改，以修复 bug 或添加功能。`bun patch` 让你无需将整个包纳入项目即可完成这些操作。

功能特点：

- 生成 `.patch` 文件，Bun 安装时会将其应用到 `node_modules` 中的依赖
- `.patch` 文件可以提交到代码仓库，并在不同安装、项目和机器之间重复使用
- `package.json` 中的 `"patchedDependencies"` 会记录已修补的包
- 修补 `node_modules/` 中的包，同时保持 Bun [全局缓存](/pm/global-cache)的完整性
- 使用 `bun patch --commit <pkg>` 提交前，可以在本地测试你的修改
- 为节省磁盘空间并保持 `bun install` 的速度，已修补的包会提交到全局缓存，并尽可能在多个项目之间共享

#### 第 1 步. 准备包进行补丁

使用 `bun patch <pkg>` 准备要修补的包：

```bash terminal icon="terminal"
# 你可以直接提供包名
bun patch react

# 如果安装了多个版本，可以指定精确版本
bun patch react@17.0.2

# 也可以提供包的路径
bun patch node_modules/react
```

<Note>
不要跳过 `bun patch <pkg>`。它可以确保 `node_modules/` 中的包目录包含一个全新的包副本，不含指向 Bun 缓存的符号链接或硬链接。

如果跳过这一步，你可能会修改缓存中的全局包。

</Note>

#### 第 2 步. 本地测试你的修改

`bun patch <pkg>` 让你可以直接安全地编辑 `node_modules/` 中的 `<pkg>`，同时保持 Bun [全局缓存](/pm/global-cache)的完整性。它的工作原理是在 `node_modules/` 中重新创建一个未链接的包副本，并将其与全局缓存中的原始包进行差异比较。

#### 第 3 步. 提交修改

当你满意修改后，执行 `bun patch --commit <路径或包名>`。

Bun 会在 `patches/` 中生成补丁文件，更新你的 `package.json` 和锁文件，并开始使用修补后的包：

```bash terminal icon="terminal"
# 你可以提供已修补包的路径
bun patch --commit node_modules/react

# 或只是包名，外加可选版本号
bun patch --commit react@17.0.2

# 指定存放补丁文件的目录
bun patch --commit react --patches-dir=mypatches

# 为兼容 pnpm，可使用 patch-commit
bun patch-commit react
```

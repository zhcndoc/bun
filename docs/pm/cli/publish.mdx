`bun publish` 会将你的包打包成 tarball，从 `package.json` 中移除 catalog 和 workspace 协议（必要时解析版本），并发布到配置文件中指定的 registry。支持 `bunfig.toml` 和 `.npmrc` 文件。

```sh terminal icon="terminal"
## 从当前工作目录发布包
bun publish
```

```txt
bun publish v1.3.3 (ca7428e9)

packed 203B package.json
packed 224B README.md
packed 30B index.ts
packed 0.64KB tsconfig.json

Total files: 4
Shasum: 79e2b4377b63f4de38dc7ea6e5e9dbee08311a69
Integrity: sha512-6QSNlDdSwyG/+[...]X6wXHriDWr6fA==
Unpacked size: 1.1KB
Packed size: 0.76KB
Tag: latest
Access: default
Registry: http://localhost:4873/

 + publish-1@1.0.0
```

如需分别执行打包和发布，请运行 `bun pm pack`，然后将输出 tarball 的路径传递给 `bun publish`。

```sh terminal icon="terminal"
bun pm pack
...
bun publish ./package.tgz
```

<Note>
  如果提供了 tarball 路径，`bun publish` 不会运行生命周期脚本（`prepublishOnly/prepack/prepare/postpack/publish/postpublish`）。只有在 `bun publish` 自行打包时才会运行这些脚本。
</Note>

### `--access`

`--access` 用于设置所发布包的访问级别，可以是 `public` 或 `restricted`。无作用域的包始终为公开包，使用 `--access restricted` 发布无作用域包会报错。

```sh terminal icon="terminal"
bun publish --access public
```

也可以在 `package.json` 的 `publishConfig` 字段中设置 `--access`。

```json package.json icon="file-json"
{
  "publishConfig": {
    "access": "restricted"
  }
}
```

### `--tag`

设置所发布包版本的标签。默认标签为 `latest`。包的初始版本总是会被打上 `latest` 标签，且会额外打上指定的标签。

```sh terminal icon="terminal"
bun publish --tag alpha
```

也可以在 `package.json` 的 `publishConfig` 字段中设置 `--tag`。

```json package.json icon="file-json"
{
  "publishConfig": {
    "tag": "next"
  }
}
```

### `--dry-run`

`--dry-run` 会运行发布流程但不会发布包，因此你可以检查实际会发布哪些内容。

```sh terminal icon="terminal"
bun publish --dry-run
```

### `--tolerate-republish`

如果包版本已存在，使用该标志时退出码为 0 而不是 1。在可能重新运行作业的 CI/CD 场景中很有用。

```sh terminal icon="terminal"
bun publish --tolerate-republish
```

### `--gzip-level`

设置打包包时使用的 gzip 压缩级别，可设为 `0` 到 `9`（默认为 `9`）。仅适用于不带 tarball 路径参数的 `bun publish`。

### `--auth-type`

如果你的 npm 账户启用了双因素认证，`bun publish` 会通过浏览器或 CLI 提示你输入一次性密码。`--auth-type` 用于告诉 npm registry 你偏好的验证方式：`web`（默认）或 `legacy`。

```sh terminal icon="terminal"
bun publish --auth-type legacy
...
此操作需要一次性密码。
输入 OTP：123456
...
```

### `--otp`

直接向 CLI 提供一次性密码。如果密码有效，`bun publish` 会跳过发布前额外的一次性密码提示：

```sh terminal icon="terminal"
bun publish --otp 123456
```

<Note>
  `bun publish` 支持使用 `NPM_CONFIG_TOKEN` 环境变量，这在通过 GitHub Actions 或其他自动化工作流发布时很有用。
</Note>

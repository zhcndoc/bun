<Note>要升级 Bun CLI 版本，请参阅 [`bun upgrade`](/installation#upgrading)。</Note>

`bun update`（别名 `bun up`）会将每个直接和传递依赖更新到其请求范围允许的最新版本。随后，它会重写 `package.json` 和 `bun.lock`。若要忽略已声明的范围，请使用 [`--latest`](#--latest)。

```sh terminal icon="terminal"
bun update
```

要更新特定的软件包，请传入其名称。名称可以是 glob 模式，`!` 用于排除：

```sh terminal icon="terminal"
bun update zod
bun update jquery@3            # move the package.json entry to the newest 3.x
bun update '@types/*'
bun update '@babel/*' '!@babel/core'
```

`bun update <package>` 会更新 `<package>` 在 `bun.lock` 中出现的所有位置，并保持其他内容不变。这同样适用于传递依赖——`bun update caniuse-lite` 会获取嵌套依赖中的修复，而不会将其添加到 `package.json`。不在 `bun.lock` 中的名称会导致错误。

更新的软件包会在安装摘要中显示为 `↑ name old → new`，当更新范围之外存在更新的主版本时，会显示 `(v3.0.0 available)`。使用 `--dry-run` 可预览更新。

### `package.json` 如何被重写

- `^1.1.0` → `^1.2.0`，`~1.1.0` → `~1.1.5`。Bun 会保留运算符。使用 [`install.exact`](/runtime/bunfig#install-exact) 或 `--exact` 时，Bun 会写入精确版本。
- 精确锁定版本、dist-tag（`"latest"`、`"next"`）和其他范围形式（`*`、`1.x`、`>=1.0.0`）会保持原样；只有 `bun.lock` 会更新。`--latest` 会重写它们。
- Bun 从不重写 `catalog:` 引用；它会改为更新根目录 `package.json` 中的 catalog 条目。
- `--no-save` 只会更新 `node_modules`，而不更改 `package.json` 和 `bun.lock`。

### 哪些内容会被保留

- Bun 从不扩大范围。依赖 `foo@^1.0.0` 的软件包永远不会获得 `foo@2.x`。
- `patchedDependencies` 中的版本只要仍在其范围内，就会保持不变。Bun 会将它们报告为 `kept name@version (patched, v1.2.3 available)`。`--latest` 和 [`bun audit fix`](/pm/cli/audit#bun-audit-fix) 会更新它们；之后请使用 [`bun patch`](/pm/patch) 重新创建补丁。
- 如果针对某个传递依赖的软件包的注册表请求失败，该软件包会保留其锁定版本，Bun 会打印警告。针对直接依赖的请求失败则会报错。

## `--interactive`

使用 `--interactive` 标志选择要更新的软件包：

```sh terminal icon="terminal"
bun update --interactive
bun update -i
```

`--interactive` 会打开一个终端界面，列出所有过时的直接依赖。Bun 会更新你选中的软件包，效果等同于运行 `bun update <name> ...`；其他软件包都会保留其锁定版本。

### 交互界面

界面显示按依赖类型分组的软件包：

```txt
? Select packages to update - Space to toggle, Enter to confirm, a to select all, n to select none, i to invert, l to toggle latest

  dependencies                Current  Target   Latest
    □ react                   17.0.2   18.2.0   18.3.1
    □ lodash                  4.17.20  4.17.21  4.17.21

  devDependencies             Current  Target   Latest
    □ typescript              4.8.0    5.0.0    5.3.3
    □ @types/node             16.11.7  18.0.0   20.11.5

  optionalDependencies        Current  Target   Latest
    □ some-optional-package   1.0.0    1.1.0    1.2.0
```

**分组说明：**

- 软件包按节标题分组：`dependencies`、`devDependencies`、`peerDependencies`、`optionalDependencies`
- 每组显示与软件包数据对齐的列标题

**列说明：**

- **软件包**：软件包名称（可能带有诸如 ` dev`、` peer` 或 ` optional` 的后缀）
- **当前版本**：当前已安装的版本
- **目标版本**：将要安装的版本（遵循 semver 约束）
- **最新版本**：最新可用版本

### 键盘操作

**选择操作：**

- **空格**：切换软件包的选择状态
- **回车**：确认选择并更新
- **a/A**：全选所有软件包
- **n/N**：全不选
- **i/I**：反选

**导航操作：**

- **↑/↓ 方向键** 或 **j/k**：移动光标
- **l/L**：切换当前软件包的目标版本和最新版本显示

**退出：**

- **Ctrl+C** 或 **Ctrl+D**：取消且不更新

### 视觉指示

- **■** 已选中的软件包（将被更新）
- **□** 未选中的软件包
- **❯** 当前光标位置
- **颜色**：红色（主版本）、黄色（次版本）、绿色（补丁版本）变更
- **下划线**：当前选中的更新目标

### 包分组

软件包根据依赖类型分组：

- **dependencies** - 常规运行时依赖
- **devDependencies** - 开发依赖
- **peerDependencies** - 同级依赖
- **optionalDependencies** - 可选依赖

在每个分组中，单个软件包可能带有后缀（` dev`、` peer`、` optional`）。

## `--recursive` 和 `--filter`

在 monorepo 中，`bun update` 只会重写你运行命令所在工作区的 `package.json`。在根目录运行时，它仍会更新 `bun.lock` 中每个工作区的传递依赖。

- `--recursive`（`-r`）会更新每个工作区的 `package.json`。
- `--filter <pattern>`（`-F`）会使用[筛选语法](/pm/filter)仅更新匹配的工作区。与 `bun install --filter` 一样，Bun 之后只会链接选中的工作区。

两者都可以与软件包名称、`--latest`、`--dry-run` 和 `--interactive` 结合使用（后者会添加一个“工作区”列）。

```sh terminal icon="terminal"
bun update --recursive
bun update --filter './packages/*'
bun update -i -r
bun update zod -r
bun update zod --filter '...^ui'
```

## `--dev`、`--prod`、`--no-optional`

限制 Bun 要更新的 `package.json` 条目：

- `--dev`（`-D`）只更新 `devDependencies`。
- `--prod`（`-P`）只更新 `dependencies` 和 `optionalDependencies`。
- `--no-optional` 跳过 `optionalDependencies`。

它们可以与名称、模式、`--latest` 和 `--interactive` 结合使用。

这些标志只会选择要更新的内容——`bun update --prod` 仍会安装 `devDependencies`。

```sh terminal icon="terminal"
bun update --dev
bun update --prod --latest
bun update -D '@types/*'
bun update -i --prod
```

## `--global`

`bun update -g` 会更新通过 `bun add -g` 安装的软件包：

```sh terminal icon="terminal"
bun update -g
bun update -g typescript
```

## `--latest`

默认情况下，`bun update` 会将每个依赖项更新到满足 `package.json` 中版本范围的最新版本。

若要不受已声明范围限制、将直接依赖更新到最新版本，请使用 `--latest`（`-L`）。Bun 会将 `package.json` 条目重写为新版本的同类范围。传递依赖仍会遵循其依赖项声明的范围。Bun 不会降级已高于 `latest` 的依赖项（例如，预发布版本）。

```sh terminal icon="terminal"
bun update --latest
bun update -L
```

在交互模式下，按 **l** 可在软件包的目标版本（遵循 semver）和最新版本之间切换。

例如，以下 `package.json`：

```json package.json icon="file-json"
{
  "dependencies": {
    "react": "^17.0.2"
  }
}
```

- `bun update` 会升级到匹配 `17.x` 的版本。
- `bun update --latest` 会升级到匹配 `18.x` 或更高版本。

---
title: "bun audit"
description: "检查已安装的包是否存在已知的安全漏洞"
---

在包含 `bun.lock` 文件的项目中运行命令：

```bash terminal icon="terminal"
bun audit
```

Bun 从 `bun.lock` 读取包列表（无需 `node_modules`），将其发送到 npm 安全公告端点，并打印报告。对于来自作用域注册表的包，Bun 会将其发送到该注册表。如果该注册表没有安全公告端点，Bun 会将这些包列为已跳过，并且它们不会影响退出代码。

`bun audit` 永远不会修改 `package.json`、`bun.lock` 或 `node_modules`。要应用修复，请使用 [`bun audit fix`](#bun-audit-fix)。

如果 Bun 未发现漏洞，命令会打印：

```
No vulnerabilities found
```

否则，Bun 会列出每个受影响的包及其严重性、简短描述和咨询链接，随后显示摘要：

```
3 vulnerabilities (1 high, 2 moderate)

  bun audit fix           upgrade the vulnerable packages within their ranges
  bun audit fix --latest  also cross major versions
```

### 过滤选项

**`--audit-level=<low|moderate|high|critical>`** - 仅报告严重性达到此级别或更高的漏洞：

```bash terminal icon="terminal"
bun audit --audit-level=high
```

**`--prod`**（`-p`、`-P`、`--production`）- 仅审计可通过 `dependencies`、`optionalDependencies` 或 `peerDependencies` 访问的包：

```bash terminal icon="terminal"
bun audit --prod
```

**`--omit=<dev|optional|peer>`** - 跳过只能通过给定依赖类型访问的包。可重复使用。`--omit=dev` 与 `--prod` 相同：

```bash terminal icon="terminal"
bun audit --omit=optional --omit=peer
```

**`--ignore <id>`** - 根据 GHSA ID 或数字 ID 忽略安全公告。可重复使用。（CVE ID 不在注册表数据中，因此无法匹配。）

```bash terminal icon="terminal"
bun audit --ignore GHSA-c2qf-rxjj-qqgw --ignore 1112918
```

这些选项仅适用于 CLI；要在每次运行时应用它们，请将其放入 `package.json` 脚本中。

### `--json`

打印注册表返回的原始 JSON 响应，而不是格式化报告：

```bash terminal icon="terminal"
bun audit --json
```

JSON 未经过过滤——`--audit-level` 和 `--ignore` 只会影响退出代码。

### `bun audit fix`

```bash terminal icon="terminal"
bun audit fix
```

运行审计，然后将每个存在漏洞的包升级到所有依赖方的版本范围都允许的最低无漏洞版本，并进行安装。只有 `bun.lock` 和 `node_modules` 会发生变化，但有一个例外：Bun 会将固定为确切版本的直接依赖视为 `^version`。如果 Bun 找到修复版本，它会重写 `package.json`（或 catalog）中的固定版本。

```
fixing:
  ms@0.7.0 → 0.7.1
  lodash@4.17.20 → 4.17.21
    package.json: 4.17.20 → 4.17.21

blocked by a dependent's range:
  minimatch@0.3.0 → 3.0.2
    express@3.21.2 depends on minimatch@0.3.0
  semver@5.7.1 → 6.3.1
    my-app depends on semver@^5.0.0
    bun audit fix --latest

no published version fixes:
  left-pad@1.3.0  GHSA-xxxx-xxxx-xxxx
    bun audit fix --ignore GHSA-xxxx-xxxx-xxxx

Fixed 2 vulnerabilities in 2 packages
5 vulnerabilities remaining
```

- **被依赖方的版本范围阻止**——没有安全版本符合某个依赖方声明的版本范围。如果该范围位于你自己的 `package.json` 或 catalog 中，`bun audit fix --latest` 可以绕过此限制。否则，请更新该依赖方或添加 [`overrides`](/pm/overrides) 条目。
- **没有已发布的修复版本**——所有已发布的版本都存在漏洞。请替换该包，或使用打印出的 `--ignore` 命令忽略此安全公告。
- 如果没有更高版本是安全的，但存在更低版本，Bun 会降级并将该行标记为 `(downgrade)`。
- 如果安全版本仍比 `--minimum-release-age` 更新，Bun 仍会安装该版本，并将该行标记为 `(newer than --minimum-release-age)`。
- Bun 会像升级其他包一样升级已修补的依赖（`patchedDependencies`）。之后使用 `bun patch` 重新创建补丁。
- 安装后，Bun 会重新审计新的 lockfile。`remaining` 数量和退出代码会根据第二次审计结果确定，因此与后续运行 `bun audit` 报告的结果一致。
- `--dry-run` 会打印计划，但不进行安装。
- `--json` 会打印一个描述计划和结果的 JSON 对象（`fixes`、`blocked`、`unfixable`、`unmatched`、`unaudited`、`vulnerableAfterInstall`、`fixed`、`remaining`、`dryRun`）。如果生命周期脚本可能会向 stdout 写入内容，请传入 `--ignore-scripts`。
- 在 `bunfig.toml` 中配置的[安全扫描器](/pm/security-scanner-api)会像运行 `bun update` 一样，对即将安装的包进行扫描。
- Bun 不接受 `--prod`、`--frozen-lockfile` 和 `--no-save`，因为这些选项会阻止写入 `bun.lock`。

### `bun audit fix --latest`

```bash terminal icon="terminal"
bun audit fix --latest
```

与 `bun audit fix` 相同，但你自己的 `package.json` 文件和 catalog 中的版本范围不再阻止修复。Bun 会重写这些范围以接受新版本，同时保留其格式（`^5.0.0` → `^6.3.1`、`~5.7.1` → `~6.3.1`，确切版本则保持为确切版本）。第三方包声明的版本范围仍会阻止修复；对于这些情况，请使用 `overrides`。

### 退出代码

如果 Bun 应用 `--audit-level` 和 `--ignore` 后没有剩余漏洞，则退出代码为 `0`；否则为 `1`。对于 `bun audit fix`，退出代码根据安装后的重新审计结果确定（或者在使用 `--dry-run` 时，根据计划确定）。

如果注册表请求失败，两个命令都会向 stderr 打印 `audit request failed`，并以 `1` 退出。

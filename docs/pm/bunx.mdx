<Note>`bunx` 是 `bun x` 的别名。安装 `bun` 时会自动安装 `bunx` CLI。</Note>

使用 `bunx` 来自动安装并运行来自 `npm` 的包。它是 Bun 版本的 `npx` 或 `yarn dlx`。

```bash terminal icon="terminal"
bunx cowsay "Hello world!"
```

<Note>
  ⚡️ **速度** — 利用 Bun 的快速启动时间，`bunx` 在运行本地安装的包时比 `npx` [快大约 100 倍](https://twitter.com/jarredsumner/status/1606163655527059458)。
</Note>

包可以在它们的 `package.json` 文件中的 `"bin"` 字段声明可执行文件。这些被称为 _包可执行文件_ 或 _包二进制文件_。

```json package.json icon="file-json"
{
  // ... 其他字段
  "name": "my-cli",
  "bin": {
    "my-cli": "dist/index.js"
  }
}
```

这些可执行文件通常是带有[ shebang 行](<https://en.wikipedia.org/wiki/Shebang_(Unix)>)的纯 JavaScript 文件，其中会指定用于运行它们的程序。以下文件使用 `node` 运行。

```js dist/index.js icon="/icons/javascript.svg"
#!/usr/bin/env node

console.log("Hello world!");
```

使用 `bunx` 运行这些可执行文件：

```bash terminal icon="terminal"
bunx my-cli
```

与 `npx` 一样，`bunx` 会先检查本地安装的包，然后再从 `npm` 自动安装该包。已安装的包会存储在 Bun 的[全局缓存](/pm/global-cache)中，以便将来使用。

## 参数和标志

要向可执行文件传递额外的命令行标志和参数，请把它们放在可执行文件名之后。

```bash terminal icon="terminal"
bunx my-cli --foo bar
```

---

## Shebang 行

默认情况下，Bun 会遵循 shebang。如果可执行文件标记为 `#!/usr/bin/env node`，Bun 会启动一个 `node` 进程来执行该文件。若要改用 Bun 的运行时执行可执行文件，请传入 `--bun` 标志。

```bash terminal icon="terminal"
bunx --bun my-cli
```

`--bun` 标志必须 _出现在_ 可执行文件名之前。位于可执行文件名 _之后_ 的标志会传递给该可执行文件。

```bash terminal icon="terminal"
bunx --bun my-cli # 正确
bunx my-cli --bun # 错误
```

## Package 标志

**`--package <pkg>` 或 `-p <pkg>`** - 从指定的软件包运行二进制文件。当二进制文件名与软件包名称不同时非常有用：

```bash terminal icon="terminal"
bunx -p renovate renovate-config-validator
bunx --package @angular/cli ng
```

要强制脚本始终使用 Bun 运行，请为其指定一个 `bun` shebang。

```js dist/index.js icon="/icons/javascript.svg"
#!/usr/bin/env bun
```

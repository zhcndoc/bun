---
title: "锁文件"
description: "Bun 的锁文件格式和配置"
---

`bun install` 创建一个名为 `bun.lock` 的锁文件。

#### 应该提交到 git 吗？

是的

#### 是否可以生成锁文件但不安装？

要在不安装到 `node_modules` 的情况下生成锁文件，请使用 `--lockfile-only` 标志。Bun 始终会将锁文件保存到磁盘，即使它与项目的 `package.json`（或多个 `package.json`）保持最新也不例外。例外情况是设置了 `--frozen-lockfile`（或 `--production`）。

```bash terminal icon="terminal"
bun install --lockfile-only
```

`bun add`、`bun remove` 和 `bun update` 也接受 `--lockfile-only`。

<Note>
  `--lockfile-only` 仍会使用注册表元数据以及 git/tarball 依赖填充全局安装缓存。
</Note>

#### 可以选择不生成锁文件吗？

要安装依赖但不创建锁文件：

```bash terminal icon="terminal"
bun install --no-save
```

要在 `bun.lock` 之外再写入一个 Yarn 锁文件：

<CodeGroup>

```bash terminal icon="terminal"
bun install --yarn
```

```toml bunfig.toml icon="settings"
[install.lockfile]
# 是否在 bun.lock 旁保存非 Bun 的锁文件
# 目前仅支持 "yarn"
print = "yarn"
```

</CodeGroup>

#### 基于文本的锁文件

Bun v1.2 将默认锁文件格式更改为基于文本的 `bun.lock`。要迁移现有的二进制 `bun.lockb`，请运行 `bun install --save-text-lockfile --frozen-lockfile --lockfile-only`，然后删除 `bun.lockb`。

有关该格式的更多信息，请参阅[博客文章](https://bun.com/blog/bun-lock-text-lockfile)。

#### 自动锁文件迁移

在没有 `bun.lock` 的项目中运行 `bun install` 时，Bun 会自动迁移现有的锁文件：

- `yarn.lock`（v1）
- `package-lock.json`（npm，`lockfileVersion` 为 2、3 或 4）
- `pnpm-lock.yaml`（pnpm）

Bun 不会迁移来自 npm 6 或更早版本的 `package-lock.json`（`lockfileVersion` 为 1）；它会打印一条警告，并改为根据 `package.json` 解析依赖。

Bun 会保留原始锁文件。验证后，你可以手动删除它。
